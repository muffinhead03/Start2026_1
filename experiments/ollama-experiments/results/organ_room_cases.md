## Case 1 — 씬 컨텍스트 없을 때 vs 있을 때 응답 비교

**실험 내용**  
`PromptBuilder`에 씬 컨텍스트를 포함하지 않았을 때와 포함했을 때 응답 비교.

**씬 컨텍스트 없는 응답**
```
주변을 잘 살펴보세요. 단서가 숨겨져 있을 수 있습니다.
```

**씬 컨텍스트 있는 응답 (hintLevel 2)**
```
오르간 주변 어딘가에 빠진 것이 있는 것 같군요... 소리가 나지 않는 이유를 생각해보세요.
```

**씬 컨텍스트 있는 응답 (hintLevel 4)**
```
파이프가 막혀있습니다. 방 곳곳에 흩어진 파이프 4개를 찾아 오르간에 설치하세요.
```

**결론**  
씬 컨텍스트가 없으면 게임과 무관한 일반적 힌트가 생성됨. `GetSceneContext()`로 씬별 오브젝트·퍼즐 구조를 상세히 서술하는 방식으로 확정.

## Case 2 — entity 질문 유형에서 엔티티 정보 누설 문제

**입력 상황**
- Phase 1 (오르간 수리 단계) — 아직 엔티티가 등장하지 않은 상태
- 질문 유형: entity

**문제 응답**
```
보이지 않는 존재가 소리를 듣고 있습니다. LP 플레이어로 주의를 돌리세요.
```

**문제점**  
Phase 1에서는 엔티티가 아직 등장하지 않았는데, 엔티티 회피 방법(LP 플레이어 활용)을 미리 알려줌. 플레이어가 아직 발견하지 않은 정보를 노출.

**시스템 프롬프트 수정**  
`"Never mention information the player has not yet discovered."` 지시 추가.

**수정 후 응답**
```
지금 이 공간에서는 엔티티가 느껴지지 않습니다. 오르간에 집중하세요.
```

## Case 3 — hintLevel 5에서 정답 직접 노출 문제

**입력 상황**
- hintLevel: 5
- 질문 유형: puzzle
- 현재 단계: 오르골 멜로디로 방 3 키패드 번호 알아내기

**문제 응답**
```
키패드에 4025를 입력하세요.
```

**문제점**  
hintLevel 5라도 정답을 그대로 노출하는 것은 게임 경험을 해침. "직접적"은 단계를 명확히 알려주는 것이지 정답 숫자를 말하는 게 아님.

**시스템 프롬프트 수정**  
`"Never reveal the answer directly."` 지시를 프롬프트 앞뒤에 중복 강조.

**수정 후 응답 (hintLevel 5)**
```
오르골이 연주한 음계 순서대로 숫자를 대응시켜 키패드에 입력하면 문이 열립니다.
```
